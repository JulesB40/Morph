# Collection UI acceptance scenarios

Implementation source: UI commits `75362dc`, `8fbb213`, `4ea6300`, plus the follow-up denial/layout correction. This is an acceptance specification, not a recorded client pass. Merge the descriptor, service, rendering and shape dependencies before compiling either loader.

Run the same cases on Fabric and NeoForge through the supervised client input/capture queue. Record the exact source revision, language, scaled GUI dimensions, actor UUID, server collection revision, request sequence and acknowledgement, complete owner snapshot and screenshot. A click or completed bridge command is not an action-success oracle.

1. **Initial load and denied selector.** Open `[` before any complete owner snapshot. Expect a loading message and disabled mutation buttons. With selector access denied by server policy, expect an explicit denial after the request acknowledgement, including when the server sends no collection snapshot. Reopen after allowing access; only a complete new snapshot enables actions.
2. **Distinct variants and localization.** Acquire a named blue baby sheep, a red adult sheep and a size-3 slime using the supported server capture path. English/French rows must display native translated species names, custom name and the actual baby/color/size labels, with distinct selection IDs. Search `bebe bleu` in French must find the blue baby sheep; search by `minecraft:sheep` must find both sheep. The UI must not rewrite a descriptor or merge species variants.
3. **Favorites and acknowledgement ordering.** Toggle the baby sheep star. Before acknowledgement/snapshot completion, its displayed favorite must remain unchanged and mutation buttons must be disabled. After both arrive, the star and favorites filter must reflect the server snapshot. Exercise snapshot-before-ack and ack-before-snapshot. Repeat for removing the last favorite while filtering favorites; expect an empty-favorites message and no stale selection.
4. **Deletion and rejection.** Arm deletion, cancel it and verify no request was sent. Arm again, then deliver a newer collection snapshot; confirmation must cancel. Confirm a non-active form and verify deletion only after the server commits. For an active small form in a player-sized no-fit space, confirm deletion: expect `NO_SPACE`, unchanged active entry and ownership, and controls re-enabled without requiring a new snapshot. Retest in open space; reset and deletion must occur atomically on the server.
5. **Keyboard and paging.** Provide at least 18 entries. Use arrow keys and Page Up/Down to navigate across page boundaries. Enter selects the highlighted row when list navigation owns focus; typing in search never activates a form. Tab/Shift-Tab must reach every enabled control with narration. Apply a snapshot while typing and verify query/caret remains usable; remove the selected entry and verify selection/page clamps.
6. **Favorite wheel.** Provide at least 10 favorites, including two variants of one species. Hold `]`, hover a card and release: exactly one select action, then close only after successful acknowledgement plus complete snapshot. Release over the empty center without a keyboard selection: no action. Click and arrow/Enter selection must also work. A rejected selection must display feedback and must not retry each tick. Rebind the favorites action to a different keyboard key and a mouse button; repeat hold/release. Check both pages and full variant text in tooltips.
7. **Preserved nametag and reset.** Toggle nametag visibility from the selector and verify authoritative actor/observer state. Reset still works when a form is active and remains server-validated for space. Close/reopen retains server favorites; reconnect/restart also requires persisted favorites from the storage/service acceptance suite.
8. **Layout and accessibility.** Capture English and French at GUI sizes 320×216, 320×240, 427×240, 640×360 and 854×480, including long custom names and empty/search/no-space states. No overlapping cards or footer controls, no unreadable unresolved translation keys. Native button scrolling and tooltips must expose truncated form names. Verify focus highlighting and narrator labels with the actual client.

Pure JUnit requirements live under `src/test/java/me/ichun/mods/morph/ui`: search normalization and conjunction, identity-preserving replacement, favorites filtering, paging/removal, acknowledgement ordering/rejection, wheel rectangle separation, and English/French key/placeholder parity. These tests do not establish real network delivery, rendering, input focus, screen-reader behavior or persisted state.

9. **Native preview.** At GUI width 640 or larger, selecting an entry displays its detached native model in the side panel. At every GUI size, the Preview button opens a dedicated larger model view and Back restores the same query and selection. Verify baby/color/size differences against the source mob, and test dragon framing separately. Deliver a descriptor revision while the preview is open, remove the entry, reload resources and change worlds; no stale model should remain. Unsupported extraction must show the explicit unavailable message and keep the rest of the selector functional. These are unticked previews with native mouse-follow orientation, not a promise of live action animation.

Known scope limits: the selector is a modal replacement with a bounded favorites wheel. In-world next/previous morph HUD parity, user-defined ordering and full mode-policy advertisement are separate work. Preview extraction and framing still require actual client screenshots. Biomass/editor presentation is not part of this collection slice.
