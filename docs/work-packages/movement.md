# Wave A: movement, pose geometry and existing mounts

Status: design only; no movement implementation or runtime validation performed for this package. Read against `docs/PARALLEL_IMPLEMENTATION_PLAN.md`, especially sections 2–4, and the movement checklist in `docs/PORT_GAP_AUDIT_2026-09-12.md`. Source inspected: alpha.8 `8955f881295ef95b42976602ca0e646449573fe1` plus the narrowly scoped Husk fixes through `48633dc63555cdd70994a774d9d932b955df87e5`. Those commits do not change movement.

## Bounded deliverable and gate

Wave A establishes native pose/eye/attachment queries, preserves controlled sustained flight and existing underwater-walking rules, and verifies placement/cleanup for the five currently rideable forms. It measures ground/water/flight motion before authoring species speed profiles. It does not add new rideable species, saddle inventories, Vex phasing, autonomous AI travel, boss locomotion, variant capture, or a second transformation clock.

The broader harness gate remains a prerequisite for production work. Parent-reported NeoForge Husk baseline/candidate results are evidence for that narrow damage fix, not completion of the rendered-client, isolation, multiplayer, lifecycle or movement gates. The new scenarios below must use frozen snapshots and both loader adapters. No production movement change is authorized by this document itself.

## Proposed contracts

1. **Pose geometry.** For a validated form descriptor and requested player pose, construct/configure a native reference using the same bounded appearance state as rendering, and query its actual `getDimensions(pose)`. Preserve the complete immutable dimension value, including attachments and `fixed`; apply player scale once. Standing/eye output must continue matching the existing native references. Proposed policy: native pose geometry replaces the synthetic universal crouch shrink; native species without a special crouch keep native dimensions. This is an intentional change to the old 5/6 policy, so revise that requirement explicitly before implementation rather than treating the old test as an oracle. Do not guess a universal sideways swim box or rotate collision from a screenshot.
2. **Query consistency.** `getDefaultDimensions`, current bounding box, `getEyeHeight`, `canFit`, pose changes and dismount clearance must agree for one descriptor/pose/transition generation. Invalid IDs, unsupported entities and constructor-time queries retain safe player geometry. Cache immutable values, not native entities; key by pose and descriptor revision once variant state exists, with world/resource lifecycle invalidation. Do not fabricate descriptor or timeline classes locally; consume the frozen shared interfaces when available.
3. **Transition handoff.** Geometry needs source/destination descriptors, server start tick, duration and generation from the shared transition contract. Until that contract is integrated, this package delivers completed-form geometry only and reports smooth collision/camera interpolation as pending. Do not silently start a separate timer. An expanding box must pass server collision checks at the applied size; rejection cannot partially select a form or corrupt saved state. Exact blocked-expansion/reset behavior belongs to the shared authoritative service policy and must be specified before transition geometry is enabled.
4. **Flight ownership.** Preserve double-jump takeoff, sustained hover, voluntary landing and no forced takeoff. Do not alter creative/spectator or external flight grants. Baseline flight speed remains the user's current ability speed until a measured profile is specified. If later writing `Abilities.flyingSpeed`, track its original value and the last Morph-written value independently of mayfly; restore only an owned, still-Morph-controlled value, and handle provider takeover/revocation and game-mode defaults. Save must exclude transient Morph permission/speed while preserving external values. Server chooses the profile; client prediction receives the same version before applying it.
5. **Measured speed profile.** Record ground/water/air displacement per server tick, acceleration curve, settled velocity, vertical drift and stopping distance under prescribed controls. Native AI/controller fixtures must state their goal, requested control speed and environment; their output is reference data, not an automatic requirement that a player match every AI maneuver. Do not equate MOVEMENT_SPEED/FLYING_SPEED equality, input multipliers, or renderer wing motion with physical parity. Species tuning requires an explicit target curve/tolerance derived from those observations. No values are invented here.
6. **Water and zombie rules.** Preserve ordinary-zombie bottom walking, Drowned swimming, passive currents/knockback and on-ground jumps. Preserve current active-flight exemption and current water-flight speed until a separate slowdown policy is specified. Bubble columns, surface exit, chicken descent, slime/magma buoyancy and iron-golem sinking are measured controls; a newly observed independent bug is recorded separately rather than automatically expanding the patch.
7. **Existing mounts only.** Preserve the five-form admission list, one rider, unsaddled interaction, spectator/self/passenger/crouch rejections and cleanup. Compare actual rider world position to native mount placement with matched pose/scale, rider size and rotation; use native attachment data plus any verified species-specific seat calculation. Do not invoke native riding code on a fake native mount and assume it controls a real player vehicle correctly. Safe dismount must produce nonintersecting bounds. Pig/strider saddles and camel/happy-ghast/nautilus seats remain later work requiring state/capability contracts.

Keep broad measurements/exploratory controls in lab tooling. ## Evidence and completion boundaries

Emit pose, descriptor revision, scale, dimensions/eyes/attachment offsets, rider/vehicle UUIDs, input sequence, server tick, position/velocity, ability flags and ability speed, external-provider state, selected policy/profile revision and assertions. Record samples after readiness/transition completion, not an arbitrary delay alone. Use per-process framebuffer capture only for visible pose/seat/camera support; never infer numeric collision correctness from an image. Use exclusive benchmarks; overloaded tick wall time must not masquerade as a speed regression.

Completion for this bounded Wave A package means both-loader verified completed-form geometry and existing-mount behavior, preserved flight/zombie controls, measured motion data with declared limitations, and an explicit pending/accepted status for species speed and shared transition policies. It does not mean all native movement, every renderer, every mod provider, new mount species or boss mechanics are complete. Stop at that boundary and submit remaining independent findings to the audit/ownership map.
